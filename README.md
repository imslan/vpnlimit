# vpnlimit

Ограничение скорости **на каждый IP клиента** для Xray / 3x-ui через nftables, с интерактивным меню в терминале.

Xray-core не умеет ограничивать скорость отдельного пользователя, а `limit_rate` в nginx stream работает на одно соединение, поэтому клиенты с несколькими соединениями (например, XHTTP) его обходят. `vpnlimit` ставит лимит на уровне ядра Linux: каждый IP получает свою полосу на указанных портах, сколько бы соединений он ни открыл.

```
═══ vpnlimit — лимит скорости на клиента ═══
  Состояние:     ● ВКЛЮЧЁН
  Скачивание:    7 Мбит/с на IP
  Загрузка:      7 Мбит/с на IP
  Порты:         443
  Автозагрузка:  да
  Клиентов:      4

  1) Выключить лимит
  2) Изменить скорость скачивания
  3) Изменить скорость загрузки
  4) Изменить порты
  5) Отключить автозагрузку
  6) Клиенты под лимитом
  9) Удалить всё (сброс)
  0) Выход
```

## Возможности

- Лимит на каждый IP отдельно, IPv4 и IPv6.
- Раздельные лимиты на скачивание и загрузку; `0` — направление без ограничения.
- TCP и UDP, поэтому XHTTP поверх HTTP/3 (QUIC) тоже ограничивается.
- Любой набор портов, например `443, 41080`.
- Интерактивное меню и команды для скриптов.
- Автозагрузка через собственную systemd-службу, по умолчанию выключена.
- Список клиентов, которые сейчас под лимитом, с автообновлением.

## Безопасность

Скрипт работает **только со своей таблицей** `inet vpnlimit`. Он не трогает:

- `/etc/nftables.conf` и службу `nftables.service`. В Debian и Ubuntu этот файл начинается с `flush ruleset`, который стирает все правила системы;
- правила ufw;
- правила Docker;
- SSH, панель и любые порты, которых нет в списке.

Перед применением правила проверяются через `nft -c`, а сама загрузка атомарна. При ошибке не меняется ничего, «половины» правил не бывает.

Пока автозагрузка выключена, лимит снимается обычной перезагрузкой. Так можно безопасно проверить всё на рабочем сервере.

## Требования

- Linux с systemd и root-доступом.
- `nftables`: `apt install nftables`. Включать службу `nftables` не нужно.
- Рекомендуется Debian 11+ / Ubuntu 22.04+. На старых ядрах скрипт честно сообщит об ошибке и ничего не применит.
- Xray должен работать в сети хоста: напрямую на сервере или в Docker с `network_mode: host`.

> **Docker в bridge-режиме не поддерживается.** Там трафик идёт через цепочку `forward`, а не `input`/`output`, и лимит срабатывать не будет.

## Установка

```bash
git clone https://github.com/USERNAME/vpnlimit.git
cd vpnlimit
sudo install -m 755 vpnlimit /usr/local/bin/vpnlimit
```

Или одной командой:

```bash
sudo curl -fsSL https://raw.githubusercontent.com/USERNAME/vpnlimit/main/vpnlimit -o /usr/local/bin/vpnlimit
sudo chmod +x /usr/local/bin/vpnlimit
```

## Использование

### Меню

```bash
sudo vpnlimit
```

Рекомендуемый порядок при первом запуске:

1. Пункт **4**: проверьте порты. По умолчанию это `443`.
2. Пункты **2** и **3**: задайте скорость. По умолчанию 7 Мбит/с.
3. Пункт **1**: включите лимит.
4. Проверьте скорость с клиента и посмотрите пункт **6**.
5. Если всё в порядке, включите автозагрузку пунктом **5**.

### Команды

| Команда | Действие |
|---|---|
| `vpnlimit` | открыть меню |
| `vpnlimit on` | включить лимит с сохранёнными настройками |
| `vpnlimit off` | выключить лимит (настройки сохраняются) |
| `vpnlimit status` | показать состояние |
| `vpnlimit 10` | 10 Мбит/с в обе стороны и включить |

## Файлы

| Путь | Назначение |
|---|---|
| `/usr/local/bin/vpnlimit` | скрипт |
| `/etc/vpnlimit/vpnlimit.conf` | настройки |
| `/etc/systemd/system/vpnlimit.service` | автозагрузка (создаётся пунктом 5) |

Пример `vpnlimit.conf`:

```bash
DL=7              # скачивание, Мбит/с (0 — без ограничения)
UL=3              # загрузка, Мбит/с
PORTS="443, 41080"
```

Файл можно править вручную; изменения вступят в силу после `vpnlimit on`.

## Как это работает

Для каждого направления создаётся динамический набор nftables. Когда от IP приходит трафик, этот IP попадает в набор и получает собственный ограничитель. Пакеты сверх лимита отбрасываются, и TCP сам снижает скорость. IP удаляется из набора через 2 минуты без активности.

1 Мбит/с = 125 000 байт/с; буфер для кратковременных всплесков — 512 КБ.

## Ограничения

- **Лимит считается на IP, а не на пользователя Xray.** Клиенты за одним NAT (например, мобильный CGNAT) делят полосу между собой. Один пользователь с устройствами в разных сетях получит лимит на каждое устройство.
- **Это не плавный шейпинг, а отбрасывание пакетов (policing).** Фактическая скорость обычно на 5–15% ниже заданной. Для таких скоростей это нормально.
- **Ограничивается всё, что работает на указанных портах**, включая fallback-сайт на 443, если он есть.

## Диагностика

```bash
nft list table inet vpnlimit     # текущие правила
systemctl status vpnlimit        # служба автозагрузки
journalctl -u vpnlimit           # ошибки при загрузке
iftop -nNP -f "port 443"         # живая скорость по IP (apt install iftop)
```

Аварийно снять лимит без скрипта:

```bash
nft delete table inet vpnlimit
```

## Удаление

В меню выберите пункт **9**, затем:

```bash
sudo rm /usr/local/bin/vpnlimit
```
