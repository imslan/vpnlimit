# vpnlimit

Ограничение скорости **на каждый IP клиента** для Xray / 3x-ui через nftables, с интерактивным меню в терминале, бустом и белым списком.

Xray-core не умеет ограничивать скорость отдельного пользователя, а `limit_rate` в nginx stream работает на одно соединение, поэтому клиенты с несколькими соединениями (например, XHTTP) его обходят. `vpnlimit` ставит лимит на уровне ядра Linux: каждый IP получает свою полосу на указанных портах, сколько бы соединений он ни открыл.

```
═══ vpnlimit — лимит скорости на клиента ═══
  Состояние:     ● ВКЛЮЧЁН
  Скачивание:    7 Мбит/с на IP
  Загрузка:      7 Мбит/с на IP
  Буст:          30 МБ на IP (восстановление ~36 с)
  Порты:         443
  Белый список:  2 адр.
  Автозагрузка:  да
  Клиентов:      4

  1) Выключить лимит
  2) Изменить скорость скачивания
  3) Изменить скорость загрузки
  4) Изменить порты
  5) Отключить автозагрузку
  6) Клиенты под лимитом
  7) Белый список (2)
  8) Изменить буст
  9) Удалить всё (сброс)
  0) Выход
```

## Возможности

- Лимит на каждый IP отдельно, IPv4 и IPv6.
- Раздельные лимиты на скачивание и загрузку; `0` — направление без ограничения.
- Буст: короткие действия (страницы, документы, почта) идут на полной скорости, лимит действует только на длительную загрузку.
- TCP и UDP, поэтому XHTTP поверх HTTP/3 (QUIC) тоже ограничивается.
- Любой набор портов, например `443, 41080`.
- Белый список IP и подсетей с комментариями: эти адреса не ограничиваются.
- Интерактивное меню и команды для скриптов.
- Автозагрузка через собственную systemd-службу, по умолчанию выключена.
- Список клиентов, которые сейчас под лимитом, с автообновлением.

## Безопасность

Скрипт работает **только со своей таблицей** `inet vpnlimit`. Он не трогает:

- `/etc/nftables.conf` и службу `nftables.service`. В Debian и Ubuntu этот файл начинается с `flush ruleset`, который стирает все правила системы;
- правила ufw;
- правила Docker;
- SSH, панель и любые порты, которых нет в списке.

Перед применением правила проверяются через `nft -c`, а сама загрузка атомарна. При ошибке не меняется ничего, «половины» правил не бывает. Адреса для белого списка тоже проверяются перед добавлением.

Пока автозагрузка выключена, лимит снимается обычной перезагрузкой. Так можно безопасно проверить всё на рабочем сервере.

## Требования

- Linux с systemd и root-доступом.
- `nftables`: `apt install nftables`. Включать службу `nftables` не нужно.
- Рекомендуется Debian 11+ / Ubuntu 22.04+. На старых ядрах скрипт честно сообщит об ошибке и ничего не применит.
- Xray должен работать в сети хоста: напрямую на сервере или в Docker с `network_mode: host`.

> **Docker в bridge-режиме не поддерживается.** Там трафик идёт через цепочку `forward`, а не `input`/`output`, и лимит срабатывать не будет.

## Установка

```bash
git clone https://github.com/imslan/vpnlimit.git
cd vpnlimit
sudo install -m 755 vpnlimit /usr/local/bin/vpnlimit
```

Или одной командой:

```bash
sudo curl -fsSL https://raw.githubusercontent.com/imslan/vpnlimit/main/vpnlimit -o /usr/local/bin/vpnlimit
sudo chmod +x /usr/local/bin/vpnlimit
```

### Обновление

Повторите установку поверх старого файла. Настройки, белый список и автозагрузка сохранятся. Если в старых настройках нет буста, он считается выключенным и поведение не меняется. Чтобы новая версия применила правила сразу, выполните:

```bash
sudo vpnlimit on
```

## Использование

### Меню

```bash
sudo vpnlimit
```

Рекомендуемый порядок при первом запуске:

1. Пункт **4**: проверьте порты. По умолчанию это `443`.
2. Пункты **2** и **3**: задайте скорость. По умолчанию 7 Мбит/с.
3. Пункт **8**: задайте буст, например 30 МБ. По умолчанию буст выключен.
4. Пункт **7**: при необходимости добавьте адреса в белый список.
5. Пункт **1**: включите лимит.
6. Проверьте скорость с клиента и посмотрите пункт **6**.
7. Если всё в порядке, включите автозагрузку пунктом **5**.

### Команды

| Команда | Действие |
|---|---|
| `vpnlimit` | открыть меню |
| `vpnlimit on` | включить лимит с сохранёнными настройками |
| `vpnlimit off` | выключить лимит (настройки сохраняются) |
| `vpnlimit status` | показать состояние |
| `vpnlimit 10` | 10 Мбит/с в обе стороны и включить |
| `vpnlimit burst` | показать текущий буст |
| `vpnlimit burst 30` | буст 30 МБ на IP (`0` — без буста) |
| `vpnlimit wl` | показать белый список |
| `vpnlimit wl add <IP> [комментарий]` | добавить IP или подсеть в белый список |
| `vpnlimit wl del <IP>` | удалить из белого списка |

## Буст

У каждого IP есть запас трафика — буст. Пока запас не израсходован, трафик идёт на полной скорости сервера, без лимита. Когда запас кончается, скорость падает до лимита. Запас постоянно пополняется со скоростью лимита.

На практике:

- открыть страницу, документ или письмо с вложением — это несколько мегабайт, они укладываются в буст и загружаются мгновенно;
- видео и большие файлы первые секунды идут быстро, затем со скоростью лимита; YouTube сам подберёт качество под длительную скорость.

Время восстановления = буст ÷ лимит. При 30 МБ и 7 Мбит/с пустой запас наполняется примерно за 36 секунд, это время показывается в меню. Если клиент не активен больше 2 минут, при возвращении он получает полный запас.

Рекомендуется 20–30 МБ. `0` — без буста (буфер 512 КБ, как в прежних версиях). Буст одинаковый для скачивания и загрузки и считается для каждого направления отдельно.

## Белый список

Адреса из белого списка не ограничиваются совсем. Поддерживаются отдельные IP и подсети, IPv4 и IPv6.

В меню (пункт **7**) можно:

- добавить IP или подсеть вручную;
- добавить свой текущий IP, с которого вы подключены по SSH;
- выбрать адрес из активных клиентов;
- удалить запись по номеру.

Из командной строки:

```bash
vpnlimit wl add 1.2.3.4 мама
vpnlimit wl add 10.0.0.0/24 офис
vpnlimit wl del 1.2.3.4
```

Список хранится в `/etc/vpnlimit/whitelist.txt`. Файл создаётся автоматически при первом добавлении; пока его нет, список считается пустым. Его можно править вручную: один адрес на строку, комментарий после `#`.

```
# мои адреса
1.2.3.4          # мама
10.0.0.0/24      # офис
2a01:4f8::/64    # домашний IPv6
```

После ручной правки выполните `vpnlimit on`. Если в файле ошибка, nft её покажет, а старые правила продолжат работать.

> Белый список тоже работает по IP. Домашний IP в списке снимает лимит со всех устройств этой сети. IP мобильного интернета обычно меняется при переподключении, поэтому для телефонов на мобильной сети белый список мало полезен.

## Файлы

| Путь | Назначение |
|---|---|
| `/usr/local/bin/vpnlimit` | скрипт |
| `/etc/vpnlimit/vpnlimit.conf` | настройки |
| `/etc/vpnlimit/whitelist.txt` | белый список (создаётся автоматически) |
| `/etc/systemd/system/vpnlimit.service` | автозагрузка (создаётся пунктом 5) |

Пример `vpnlimit.conf`:

```bash
DL=7              # скачивание, Мбит/с (0 — без ограничения)
UL=3              # загрузка, Мбит/с
BURST=30          # буст, МБ на IP (0 — без буста)
PORTS="443, 41080"
```

Файл можно править вручную; изменения вступят в силу после `vpnlimit on`.

## Как это работает

Направления считаются с точки зрения клиента:

| В меню | Для сервера | Цепочка nftables |
|---|---|---|
| Скачивание | исходящий трафик с порта → клиенту | `output` |
| Загрузка | входящий трафик от клиента → на порт | `input` |

В начале каждой цепочки стоит проверка белого списка: такие адреса пропускаются без ограничения.

Для остальных адресов создаётся динамический набор. Когда от IP идёт трафик, IP попадает в набор и получает **собственный** ограничитель («ведро с жетонами»). Пакеты сверх лимита отбрасываются, и TCP/QUIC сами снижают скорость. Через 2 минуты без активности IP удаляется из набора.

1 Мбит/с = 125 000 байт/с. Объём «ведра» — значение буста; без буста — 512 КБ.

Ограничивается только плечо «клиент ↔ сервер». Запросы Xray в интернет не попадают под правила, но выравниваются сами: Xray не может отдать клиенту больше лимита, поэтому и из интернета не тянет лишнего.

## Ограничения

- **Лимит считается на IP, а не на пользователя Xray.** Клиенты за одним NAT (например, мобильный CGNAT) делят полосу между собой. Один пользователь с устройствами в разных сетях получит лимит на каждое устройство.
- **Все порты из списка делят один лимит на IP.** Клиент, который использует два inbound одновременно, получит лимит на оба вместе.
- **Общего потолка на сервер нет:** 10 клиентов по 7 Мбит/с могут занять до 70 Мбит/с, а в моменты буста — больше.
- **Это не плавный шейпинг, а отбрасывание пакетов (policing).** Фактическая скорость обычно на 5–15% ниже заданной. Пинг при этом не растёт.
- **Спидтест при включённом бусте показывает среднее** между полной скоростью в первые секунды и лимитом. Длительная скорость равна лимиту.
- **Подтверждения (ACK) скачивания идут через лимит загрузки.** Не ставьте загрузку ниже ~1 Мбит/с, иначе начнёт проседать и скачивание. `0` (без ограничения) тоже подходит.
- **Ограничивается всё, что работает на указанных портах**, включая fallback-сайт на 443, если он есть.

## Сколько ставить

| Задача | Нужно примерно |
|---|---|
| Сайты, мессенджеры, ИИ-чаты | 1–3 Мбит/с |
| Видеозвонки | 1.5–3 Мбит/с |
| Instagram Reels, YouTube 720p | 2.5–4 Мбит/с |
| YouTube 1080p | ~5 Мбит/с |
| 4K-видео | 15–20 Мбит/с |

7 Мбит/с хватает для повседневной работы и 1080p с небольшим запасом. Если пользователи сидят через общий домашний Wi-Fi, разумно поднять до 10 Мбит/с. С бустом 20–30 МБ сайты и документы открываются на полной скорости даже при небольшом лимите.

## Диагностика

```bash
nft list table inet vpnlimit     # текущие правила и белый список
systemctl status vpnlimit        # служба автозагрузки
journalctl -u vpnlimit           # ошибки при загрузке
iftop -nNP -f "port 443"         # живая скорость по IP (apt install iftop)
```

Аварийно снять лимит без скрипта:

```bash
nft delete table inet vpnlimit
```

## Удаление

В меню выберите пункт **9**: удалятся правила, автозагрузка, настройки и белый список. Затем:

```bash
sudo rm /usr/local/bin/vpnlimit
```
